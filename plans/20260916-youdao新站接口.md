# 待办计划：切换到有道新站接口，修复 `'` 和 `&` 查不到词的问题

状态：**pending，未开工**。issue #82 里的百分号部分已在 2026-09-16 单独修复
（`internal/query/online.go` 改用 `url.PathEscape`），本计划只处理剩下的部分。

## 要解决的问题

`kd` 目前走的是有道的旧地址 `http://dict.youdao.com/w/<词>/`
（`internal/query/online.go` 里的 `youdaoLegacyBaseURL`）。这个地址对
含 `'` 或 `&` 的查询词会自己做两次 HTML 转义，导致查不到词：

| 命令 | 现象 |
| --- | --- |
| `kd aren't` | Not found |
| `kd AT&T` | 返回的是 `at` 的词条 |
| `kd -t "an old horse won't forget the way"` | 译文里出现 `；#x27；` |

这不是客户端转义没做对。2026-09-16 用 curl 直接验证过，把引号、`&` 按标准
方式编码成 `%27`、`%26` 之后结果完全一样：

```shell
curl -s "http://dict.youdao.com/w/aren%27t/" | grep -o '<title>[^<]*'
# 【aren&amp;amp;#x27;t】什么意思_英语aren&amp;amp;#x27;t的翻译_...

curl -s "http://dict.youdao.com/w/AT%26T/" | grep -o '<title>[^<]*'
# 【at&amp;amp;t】什么意思_...

curl -s "http://dict.youdao.com/w/an%20old%20horse%20won%27t%20forget%20the%20way/" \
  | grep -o "一匹老马[^<]*"
# 一匹老马；#x27；我忘了路
```

也就是说旧接口对这批词是坏的，只能换接口。

## 新接口

有道新站 `https://dict.youdao.com/result?word=<词>&lang=en` 这几个词都正常。
同日验证：

```shell
curl -s "https://www.youdao.com/result?word=aren%27t&lang=en" | grep -o '<title>[^<]*'
# aren&#x27;t
```

页面是服务端渲染的，HTML 里就有释义、例句和音标，不需要跑 JS。
抓下来去掉标签后能看到：

> 英 / ɑːnt / 美 / ɑːrnt /
> abbr. are not 的缩略形式，表示"不是"；口语疑问句或附加疑问句中可代替 am not
> 双语例句 1 We're going to crash, aren't we? 我们要坠毁了，是不是？《牛津词典》

## 工作量在哪

新站的 DOM 结构跟旧页面完全不同，`internal/query/youdao.go` 里的
`parseKeyword` / `parseParaphrase` / `parsePronounce` / `parseCollins` /
`parseExamples` / `parseMachineTrans` 全部需要针对新结构重写一套，
不是改几个选择器能了事的。`requestYoudaoWith` 已经把 `baseURL` 参数化了，
请求层这部分改动很小。

## 未验证，开工前需要先确认的事

以下几条都没有实测，不要当成事实引用：

1. **新站对长文本翻译（`kd -t`）是否也可用。** 上面只验证了单词查询。
   核验方式：`curl -s "https://dict.youdao.com/result?word=<一整句>&lang=en"`，
   看返回里有没有整句译文。如果没有，长文本可能得保留旧路径或另找入口。
2. **中文查词（`ch` 表那条路径）在新站是什么参数。** `lang=en` 是英译中，
   中译英的参数未知。
3. **柯林斯词典、星级、词频（CET4/TEM4 这类标签）新站是否还有。**
   没有的话要决定是降级展示还是保留旧接口做补充。
4. **反爬强度。** 新站页面 400KB 左右，且带 UA 校验的可能性比旧站高。
   需要确认现有的随机 UA（`pkg.GetRandomUA`）够不够，会不会触发风控。
5. **缓存兼容。** `en` / `ch` 两张表里存的是序列化后的 `model.Result`。
   如果新解析器填充的字段跟旧的不一致（比如柯林斯部分为空），
   要想清楚是否需要像 `internal/cache/sanitize.go` 那样加一次版本迁移，
   以及离线词库 ZIP 里的老数据怎么处理。

## 建议的做法

考虑到上面这些不确定性，倾向于分两步：

1. 先只写请求层加一个新站的探测脚本或临时测试，把上面 5 条逐一核实，
   把结论写回本文件；
2. 结论清楚之后再决定是"整体切换"还是"新站为主、旧站兜底"，
   然后才动 `youdao.go` 的解析代码。

不建议在第 1 步没做完之前直接开写解析器。
